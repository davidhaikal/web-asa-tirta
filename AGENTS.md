# AGENTS.md

Laravel 12 app (PHP ^8.2, Blade + Vite 5 + Tailwind 3) for "ASA Tirta", an Indonesian water company: production, QC, warehouse, cashier/POS, sales, purchasing, billing, delivery, and management reports. UI and comments are in Indonesian.

## Commands

- `composer setup` — composer install + copy `.env` + key:generate + migrate + `npm run build`
- `composer dev` — runs `artisan serve` + `queue:listen` + `pail` (logs) + `npm run dev` together; or run `php artisan serve` and `npm run dev` separately
- `composer test` — runs `artisan config:clear` then `artisan test`
- Single test: `php artisan test --filter=TestName::method`
- Format: `vendor/bin/pint` (no `pint.json`, default preset)
- No CI workflows, no pre-commit hooks, no Pest (PHPUnit 11 only)

## Database & setup gotchas

- Local `.env` uses **MySQL**: db `web_asa_tirta` at 127.0.0.1, user `root`, empty password (Laragon). `.env.example` says sqlite but that is stale — create the MySQL database first (or edit `.env`) before `migrate`.
- Tests always run on in-memory sqlite (set in `phpunit.xml`), regardless of `.env`.
- `php artisan db:seed` creates one user per role: `{role}@example.com` / password `password` — **exactly the 5 skripsi roles**: qc, gudang, keuangan, kasir, driver (reduced from 8 on 2026-09-30, approved).
- Table names are irregular. Some models set `$table` (`Pengiriman` → `pengiriman`, `PurchaseOrder` → `purchase_orders`), others rely on default pluralization (`Produk` → `produks`). Always verify against `database/migrations/` before writing queries.
- `create_dummy.php` at repo root is a manual dummy-data script (not an artisan command); it calls Eloquent directly and needs a booted app (e.g. run via tinker).
- Driver "bukti foto" uploads use the `public` disk — images won't display until `php artisan storage:link` is run (no symlink exists in the repo).

## Architecture notes

- All routes are in one flat `routes/web.php` (no API routes, no Blade components, no external API/email/payment integration — verified). When adding a controller, add the `use` import at the top. **Refactored 2026-09-29 (approved):** all duplicate URI registrations removed; dead imports removed (`AuthController`, `MarketingController`, `HomeController`, `DriverDashboardController`, `DriverPengirimanController`, `ProduksiController`, `PenjualanController`); broken legacy `resource('penjualan')` + `POST /penjualan` removed (a GET that attempted a DB insert); `/invoice` + `/permintaan-uang` routes + sidebar links removed (controllers never existed — feature absent from codebase); `/test` removed; `route:list` works again.
- ⚠️ **Route-name shadowing trap:** `RouteCollection` keys by `method+URI` — a later route with the same URI **overwrites** the earlier one, and `refreshNameLookups()` rebuilds names from the survivors, so the overwritten route's name is silently lost (was the root cause of the `stok.index` admin 500s). Never register two routes on the same URI with different names. Current arrangement: name `keuangan.penagihan` (sidebar) lives on `GET /keuangan/tagihan` (own URI), while `GET /keuangan/penagihan` serves `penagihan.index` (PenagihanController) — both render the same tagihan list.
- Role-based access: a plain string `role` column on `users`; `role:` middleware alias (`app/Http/Middleware/RoleMiddleware.php`, registered in `bootstrap/app.php`); on mismatch it **aborts 403** (guest → redirect login). Login redirects by role (`LoginController::authenticated`).
- **All module routes are protected (5-role scope, fixed 2026-09-30, approved):** `/produk*` + `/gudang*` + `/stok*` → `gudang`; `/kasir*` + `/invoice` → `kasir`; `/qc*` → `qc`; keuangan group + `resource('pembelian')` + penagihan block → `keuangan`; `/driver*` → `driver`; `/pengiriman/status` + `/pengiriman` prefix → `gudang,driver`; `/laporan` → `gudang,kasir,keuangan` (use case "Laporan Sistem"). Plus 5 role-prefix groups (`/qc`, `/pengiriman`, `/gudang`, `/keuangan`, `/driver`). Public: only `/`, `/login` (+ framework `/up`). **Removed 2026-09-30** (roles admin/marketing/produksi/manajemen deleted): `/dashboard`, `/po` (+setujui/tolak), `/admin/*` (users), `/manajemen/*` (dashboard/laporan/target), `/produksi*` (dashboard/form), `/register`, and all `admin`/`marketing`/`manajemen`/`produksi` entries in role groups.
- `app/Providers/RouteServiceProvider.php` is dead code — it is not registered in `bootstrap/providers.php` (which only lists `AppServiceProvider`). The role alias lives in `bootstrap/app.php`.
- Exports: Excel via maatwebsite/excel (classes in `app/Exports/`), PDF via barryvdh/laravel-dompdf.
- Views: Blade, one folder per module under `resources/views/`. **Layouts (unified since 2026-09-30):** `layouts/app.blade.php` = the single shell for ALL 5 roles — kasir design system (teal `#127369`, Space Grotesk, `k-*` classes), **left sidebar** (brand + per-role menu with Bootstrap Icons, user chip + logout at bottom; off-canvas + hamburger <992 px), flash rendered ONCE in the shell (`k-alert`, auto-dismiss 4.5 s), two-step confirm (`js-confirm`), print CSS (hides sidebar). `layouts/kasir.blade.php` is now a thin `@extends('layouts.app')` alias — kasir views are untouched (their `k-page-head`/`k-*` markup is part of the shell CSS). The shell re-skins Bootstrap primary to teal (`--bs-primary-rgb` + explicit `.btn-primary`/`.btn-outline-primary` `--bs-btn-*` overrides) so legacy module views (btn-primary, text-primary, links, form focus, pagination) follow the theme automatically; old layout vars (`--muted`/`--ink`/`--card`/`--bg`/`--primary`) are redefined for compat (used by `modules/*` views). Per-view flash blocks were removed from 12 module views (driver/pengiriman, gudang/{barang_keluar,laporan}, stok/index, produk/index, keuangan/{pelanggan,piutang,pembelian,pembelian_tambah,pembelian_edit,pembelian_show,penagihan}) — flash comes from the shell only. Hardcoded legacy blues (#0d6efd/#2563eb/#3b82f6) swapped to teal in 8 module views.
- Only default `ExampleTest`s exist (Unit + Feature); no test fixtures or factories beyond `UserFactory`.
